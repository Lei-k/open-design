# Web multi-user test pool (#11, epic #9)

Status: local, test-only backend proof. The mode remains loopback-only and available solely through the direct `startServer({ multiUser })` test option. Data paths follow root `AGENTS.md`.

`POST /api/runs` validates and binds the actor, managed project, conversation and test-mock request before inserting a durable `queued` row in the main daemon SQLite database. At most three queued rows may belong to one account. Only one row per account may be active. The test-mock pool defaults to two slots; `claude` and `codex` always have zero and cannot be enrolled here. Queue wait has no worker-time charge. A full queue returns `409 MULTIUSER_QUEUE_LIMIT`; a request made at or above its budget returns `429 MULTIUSER_QUOTA_EXHAUSTED`.

The dispatcher selects the eligible account with the oldest persisted dispatch turn, then takes that account's oldest queued row. Accounts without a prior turn go first in queue order. This rotates across all backlogged accounts, including after a restart, while preserving FIFO within each account. It rechecks the ledger's rolling seven-day balance at dispatch. An ineligible queued row remains queued and is rechecked on a pool change, a free-slot event, and once per minute while a slot is free, so rolling-window expiry eventually releases it. The owner sees `queued`, `running`, or a terminal status; `queuePosition` is the ordinal among that owner's queued rows and is null otherwise. The owner-scoped SSE stream persists `queued`, `start`, agent output and terminal events. Foreign, unowned and missing ids return the same 404.

The existing private `WorkerQuotaLedger` starts when the mock worker is dispatched and closes idempotently at exit, failure, or cancellation. The company-internal default budget is 30 hours (1,800 active worker-minutes) across providers in a rolling 7×24-hour window. It is admin-adjustable, not a provider billing limit. A run admitted below budget may complete beyond it; the full elapsed time is charged, with no quota-only termination of active work. Admin overrides accept integer minutes from 0 to 10,080. Ledger admission still enforces one active run per account.

Dispatch rejects a stored request that is not a JSON object with a string `message` while the row is still queued (`MULTIUSER_RUN_REQUEST_INVALID`): no runtime directory, ledger admission, worker-time charge, company turn or start event. The validated stored text, including the mock's `delayMs`, is passed unchanged to stdin. After ledger admission, the active mark, company turn and start event commit together; live SSE starts only after commit. A rejected start transaction or launcher failure before child registration closes the admitted ledger entry and fails the row with `MULTIUSER_RUN_START_FAILED`. A rolled-back transaction consumes no company turn or start event; a committed start retains them. Dispatch continues to the next eligible row.

Clean shutdown first ends queued SSE responses and stops pool timers, then kills and waits within a bound for active mock workers. Their ledger entries close at exit and their run rows become `canceled` with `output.reason = "daemon_shutdown"`; daemon downtime is free. If a child does not exit after TERM and KILL bounds, its row becomes `failed` with `output.reason = "shutdown_timeout"` and the ledger closes at that bound. On crash recovery, active rows become failed and their ledger entries close at restart time, conservatively charging the unobserved interval. Ordinary queued rows stay queued and dispatch when capacity is available. A queued row with an already active or terminal ledger entry is failed with `output.reason = "ledger_admission_replayed"`; dispatch continues to the next eligible row. This covers crashes during either half of the two-database handoff. Session revocation, account deactivation, role changes and admin password resets cancel both queued and active rows. Queued cancellation charges nothing.

Admin-only `GET /api/admin/pool` returns provider capacity, active and queued counts, and usage/budget/remaining totals keyed by account id. It contains no project names, prompts, outputs or credentials. `PUT /api/admin/pool/providers/:providerId` changes only test-mock capacity (0–16); a positive Claude/Codex value returns `403 MULTIUSER_PROVIDER_DISABLED`. `PUT /api/admin/pool/users/:id/quota` sets a verified account's budget. Capacity changes have append-only audit rows in the main run database; quota changes have append-only audit rows in the ledger database so the override and its audit commit together. Rows record admin account id, target id, value and time. These operational endpoints have no Web UI in this test-only slice.

Personal-subscription runs (#18, `executionSource: "personal_subscription"`) share the durable run table but use a separate lane. They never count toward the test-mock capacity, the company queue limit, the active-run rule or the worker-time ledger. Their own limits are 1 active and 3 queued per user (`409 MULTIUSER_PERSONAL_QUEUE_LIMIT`). An admin-set host-wide ceiling (default 4, 0–16, audited as `capacity` / `personal-subscription`) caps concurrent personal workers, and rotation across users is by a separate personal turn table. Omitting `executionSource`, or sending `company_pool`, keeps every behaviour above unchanged. Details: `web-multiuser-personal-subscription.md`.
