# Web multi-user test pool (#11, epic #9)

Status: local, test-only backend proof. The mode remains loopback-only and available solely through the direct `startServer({ multiUser })` test option. Data paths follow root `AGENTS.md`.

`POST /api/runs` validates and binds the actor, managed project, conversation and test-mock request before inserting a durable `queued` row in the main daemon SQLite database. At most three queued rows may belong to one account. Only one row per account may be active. The test-mock pool defaults to two slots; `claude` and `codex` always have zero and cannot be enrolled here. Queue wait has no worker-time charge. A full queue returns `409 MULTIUSER_QUEUE_LIMIT`; a request made at or above its budget returns `429 MULTIUSER_QUOTA_EXHAUSTED`.

The dispatcher takes the oldest eligible row for an account. After selecting an account, it gives a different eligible account the next free slot when one is waiting; this yields round-robin service across accounts and FIFO within each account. It rechecks the ledger's rolling seven-day balance at dispatch. An ineligible queued row remains queued and is rechecked on a pool change, a free-slot event, and once per minute while a slot is free, so rolling-window expiry eventually releases it. The owner sees `queued`, `running`, or a terminal status; `queuePosition` is the ordinal among that owner's queued rows and is null otherwise. The owner-scoped SSE stream persists `queued`, `start`, agent output and terminal events. Foreign, unowned and missing ids return the same 404.

The existing private `WorkerQuotaLedger` starts when the mock worker is dispatched and closes idempotently at exit, failure, or cancellation. The default budget is 120 active worker-minutes across providers in a rolling 7×24-hour window. A run admitted below budget may complete beyond it; the full elapsed time is charged, with no quota-only termination of active work. Admin overrides accept integer minutes from 0 to 10,080. Ledger admission still enforces one active run per account.

On startup, active run rows are marked failed and their ledger entries closed at restart time. This conservatively charges the unobserved interval after a crash; exact worker stop time cannot be reconstructed from these two stores. Ordinary queued rows stay queued and dispatch when capacity is available. A crash inside the two-database admission handoff may leave a queued row with an already-started ledger entry; reconciliation closes that entry and fails that one row because the ledger's immutable run id cannot be admitted twice. This is the explicit failure case, not a general queue reset. Session revocation, account deactivation, role changes and admin password resets cancel both queued and active rows. Queued cancellation charges nothing.

Admin-only `GET /api/admin/pool` returns provider capacity, active and queued counts, and usage/budget/remaining totals keyed by account id. It contains no project names, prompts, outputs or credentials. `PUT /api/admin/pool/providers/:providerId` changes only test-mock capacity (0–16); a positive Claude/Codex value returns `403 MULTIUSER_PROVIDER_DISABLED`. `PUT /api/admin/pool/users/:id/quota` sets a verified account's budget. Capacity changes have append-only audit rows in the main run database; quota changes have append-only audit rows in the ledger database so the override and its audit commit together. Rows record admin account id, target id, value and time. These operational endpoints have no Web UI in this test-only slice.
